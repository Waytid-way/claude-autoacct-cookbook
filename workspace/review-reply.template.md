# แบบตอบผลตรวจ needs-review (ทางสำรอง — ใช้เมื่อตอบคำถาม Pi บนหน้าจอไม่ได้)

ช่องทางหลัก: ตอบคำถามที่ Pi ถามบนหน้าจอ (กดตัวเลือก/พิมพ์เหตุผล) — ไม่ต้องก๊อปอะไรทั้งนั้น ฟอร์มนี้มีไว้สำหรับรีวิวนอก Pi เท่านั้น (อีเมล/ออฟไลน์) Pi ห้ามเดาแทน ช่องไหนว่าง Pi จะถามกลับ ไม่เติมเอง

```text
เคส: <file> / cid <correlationId>
ผู้ตรวจ: <ชื่อ> / วันที่ตรวจ: <YYYY-MM-DD>

ผลตรวจ: (คงไว้ข้อเดียว ลบที่เหลือ)
[ ] ยืนยันตามนี้ → Dr <รหัสบัญชี> / Cr <รหัสบัญชี>
[ ] แก้ไขตามนี้ → <ฟิลด์: ค่าใหม่, ...>
[ ] ขอหลักฐานเพิ่ม → <ขาดอะไร>

เหตุผล (บังคับ 1-2 บรรทัด → กลายเป็น resolution note):
<ทำไมถึงตัดสินแบบนี้>

ชื่อไม่ตรง GL? (ถ้ามี: ยืนยันว่าเป็น entity เดียวกัน + หลักฐาน ห้าม rename เงียบ)
<เช่น ใบเขียน "ABC Co." แต่ GL คือ "ABC TH" — ยืนยันเจ้าดียวกันจาก TaxID ...>
```

```text
ชื่อไม่ตรง GL? (ถ้ามี: ยืนยันว่าเป็น entity เดียวกัน + หลักฐาน ห้าม rename เงียบ)

```

## แต่ละช่องไปไหนต่อ (เผื่อสงสัยว่าถามทำไม)

| ช่อง | ไปไหน |
|---|---|
| ผลตรวจ + บัญชีที่เลือก | Candidate — รอ senior validate ก่อนเป็น Trusted เข้า Edge Log |
| เหตุผล | resolution note บน Evidence Link (method/confidence/evidence ครบชุด) |
| ฟิลด์ที่แก้ | กลับไป rerun pipeline แล้วตรวจ triple ใหม่ |
| ชื่อไม่ตรง GL | บันทึกเป็น resolution note ห้าม rename เงียบ |
| ขอหลักฐานเพิ่ม | ไฟล์ค้าง needs-review รอ rerun ไม่ skip |
| ผู้ตรวจ + วันที่ | human authority + valid period ของ Trusted (ไม่มี = อ้างเป็นความจริงไม่ได้) |
